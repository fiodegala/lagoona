# Project rules

- Sales action attribution uses one nullable action-tag foreign key on each POS sale, shared tag management, and the dashboard's filtered sales; tags are deactivated rather than deleted to preserve historical reporting and avoid double-counting revenue.

- Cashback reminders are generated in the database by a trigger on `pos_sales` (`upsert_cashback_reminder`), snapshotting the rules at sale time (old sales get reminders on demand via `create_cashback_reminders_from_sales`, marked `source='sale_manual'`); the popup only reads `cashback_reminders` and marks status via the `set_cashback_reminder_status` RPC — why: every sale path (PDV, edits, cancellations) is covered without touching client sale code.
- Store scope: `user_roles.store_id` is the primary store; extra stores a manager runs live in `user_extra_stores`, and RLS/app code use `user_store_ids()` / `managedStoreIds` for "my stores" — why: managers can run several stores without duplicating role rows.
- Birthday reminders compute annual occurrences dynamically from `customers.birthday` via `get_birthday_reminders` (using `COALESCE(c.store_id, latest pos_sale.store_id)`), store only per-year send status in `birthday_reminders` via `set_birthday_reminder_status`, and generate WhatsApp copy from the attached gift image via the `generate-birthday-message` edge function — why: annual birthdays recur automatically without cron jobs or duplicate rows.
